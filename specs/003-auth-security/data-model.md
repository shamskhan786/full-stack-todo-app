# Data Model: Authentication & Security

**Feature**: 003-auth-security
**Date**: 2026-02-10

## Entities

### User (managed by Better Auth)

Better Auth creates and manages user records in PostgreSQL. The schema
is owned by Better Auth's migration system — the backend never writes
to this table directly.

| Field | Type | Constraints | Notes |
|-------|------|-------------|-------|
| id | UUID | PK | Becomes JWT `sub` claim |
| name | VARCHAR | NOT NULL | Display name |
| email | VARCHAR | UNIQUE, NOT NULL | Case-insensitive, trimmed |
| emailVerified | BOOLEAN | NOT NULL | Default false |
| image | VARCHAR | nullable | Profile image URL |
| createdAt | TIMESTAMP | NOT NULL | Auto-set |
| updatedAt | TIMESTAMP | NOT NULL | Auto-set |

**Password storage**: Stored in a separate `account` table by Better
Auth. Passwords are hashed before storage (Argon2/bcrypt depending on
Better Auth version). Plaintext passwords are never persisted.

### Session (managed by Better Auth)

Better Auth maintains server-side sessions for its own internal use.
The backend never reads sessions — it only verifies JWTs.

| Field | Type | Constraints | Notes |
|-------|------|-------------|-------|
| id | UUID | PK | Session identifier |
| userId | UUID | FK → user.id | Session owner |
| token | VARCHAR | UNIQUE | Session token |
| expiresAt | TIMESTAMP | NOT NULL | Session expiry |
| createdAt | TIMESTAMP | NOT NULL | Auto-set |
| updatedAt | TIMESTAMP | NOT NULL | Auto-set |

### JWT (stateless, not persisted)

JWTs are issued by Better Auth's JWT plugin and are **not stored** in
any database. The token is self-contained.

| Claim | Type | Source | Notes |
|-------|------|--------|-------|
| sub | string (UUID) | user.id | Principal identity |
| iat | number | Issuance time | Unix timestamp |
| exp | number | Expiry time | Unix timestamp |
| iss | string | Better Auth | Issuer identifier |

**Signing**: EdDSA (Ed25519). Keys auto-generated by Better Auth and
served via JWKS endpoint at `/api/auth/jwks`.

### Task (managed by backend)

See `specs/001-todo-backend-api/` for full schema. Auth-relevant field:

| Field | Type | Constraints | Notes |
|-------|------|-------------|-------|
| user_id | UUID | NOT NULL, indexed | Must match JWT `sub` |

All queries include `WHERE user_id = :user_id` to enforce isolation.

## Entity Relationships

```text
User (Better Auth)
  │
  ├── 1:N → Session (Better Auth internal)
  │
  ├── 1:N → JWT (stateless, issued on sign-in)
  │
  └── 1:N → Task (backend, scoped by user_id)
```

## Cross-Service Boundary

```text
┌─────────────────────────┐     ┌──────────────────────────┐
│   Frontend (Next.js)    │     │    Backend (FastAPI)      │
│                         │     │                          │
│  Better Auth manages:   │     │  Owns:                   │
│  - user table           │     │  - task table            │
│  - session table        │     │                          │
│  - account table        │     │  Reads (verify only):    │
│  - jwks table           │     │  - JWKS public keys      │
│                         │     │  - JWT `sub` claim       │
│  Issues: JWT tokens     │────▶│  Never reads:            │
│                         │     │  - user table            │
│                         │     │  - session table         │
└─────────────────────────┘     └──────────────────────────┘
```

The backend has **zero direct access** to Better Auth's user/session
tables. User identity is communicated exclusively via JWT `sub` claim.
